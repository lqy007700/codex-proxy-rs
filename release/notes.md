# v3.35.1+lqy007700.v3

## 按需恢复跨渠道历史

- API 密钥的“跨渠道聊天兼容”改为正常保留历史推理和原生续接，不再因为开启开关就在每次请求前清空推理
- 仅在上游明确返回 `invalid_encrypted_content`、尚未出现有效业务输出或外部副作用且输入可独立重放时，尝试一次同账号、同传输兼容恢复；HTTP/SSE、WebSocket、OpenAI OAuth 与 API Key 上游共用该规则
- 恢复整项移除失败输入中的加密推理，保留可见消息、消息阶段、工具调用和结果的顺序、ID 与正文，不修改或替换推理 ID
- 恢复产生有效输出或成功完成后，只记录被排除旧项的指纹；后续自包含请求精确过滤这些旧项，继续保留新产生的推理
- 正常增量续接和上游支持的压缩历史不再提前拒绝；增量请求遇到密文错误时请求客户端完整重放，不把增量或不可迁移的业务密文删减后重发

## 恢复边界与可靠性

- 每个逻辑请求最多增加一次兼容尝试，不消耗换号次数、不重置其他重试预算；转换结果贯穿当前请求的后续尝试，避免服务故障重试重新带回旧密文
- 已交付的可替换元数据前导不会单独禁止恢复；实际输出、外部副作用、发送结果不明、取消和截止时间仍阻止新增恢复发送
- 排除指纹按 Key、线程或会话、目标账号、凭据版本和端点隔离；缓存原子合并、命中续期并限制容量，不保存原始密文或聊天正文
- 缓存读写各最多等待 100ms，故障或记录超限不覆盖模型响应，也不退化为每次清空推理；记录缺失时后续请求可能再次经历一次拒绝与恢复

## 升级事项

- 已开启 `portableHistory` 的 Key 自动采用按需恢复行为；开关仍默认关闭，关闭时保持原生处理，更新省略或 `null` 仍保留原值
- 本版本不新增 PostgreSQL 迁移，恢复记录使用可过期的 Redis 缓存
- 自动恢复需要客户端提供自包含的可读消息及配对的工具调用与结果；网关不能证明客户端没有遗漏早先消息，也不能解密或补回推理状态，不保证所有密文错误都能恢复
- 关闭开关可停用自动恢复及旧项过滤，但不会启用旧版每次清空推理的模式；如需旧行为，应回滚到原版本
