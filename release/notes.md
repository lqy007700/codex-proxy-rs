# v3.29.3+lqy007700

## 请求记录与诊断

- 请求明细置顶，统计概览移到下方并默认展开；所有请求、成功、失败筛选仅保留图标，继续默认显示所有请求
- 错误详情采用新版布局，集中展示请求上下文、错误位置和尝试链路，保留快捷提示、实际尝试次数、诊断时间线、关联请求及后端诊断包下载
- 错误列表增加独立错误摘要，保留取消与未完成状态的区别；日期筛选支持最近 31 天，默认查看今天
- Key 用量页从最终请求记录查询，补齐状态筛选与错误信息，保留失败请求已记录的 Token 和费用

## 额度与请求恢复

- 支持套餐额度耗尽后使用可用点数：上游明确报告点数可用且没有支出或工作区限制时，账号仍可参与调度；失败后的额度回读可解除耗尽状态，但不会自动重发本次失败请求
- 改进额度窗口到期后的后台复查与恢复，结合已确认的耗尽窗口、重置时间和新额度事实，避免仅凭时间到期提前恢复账号
- 新增即将到期重置卡的自动使用设置，默认关闭，支持提前时间和周剩余额度条件；未决消费沿用持久化幂等键，重启后继续核对结果
- 保留本仓库的失败恢复策略：容量拒绝、可恢复的显式 `500`、`503` 和无状态码 `server_error` 共享请求内额外 5 次恢复预算，先在原账号额外重试最多 3 次，再逐次换号最多 2 次；继续遵守重放、超时与副作用边界
- 选号耗尽时保留最后一次上游失败原因，区分会话策略限制与账号故障，避免错误冻结账号

## 账号与代理管理

- 账号并发详情展示正在执行请求的 Key、模型、来源 IP、开始时间及持续时间，支持刷新
- 代理支持批量创建、批量测试和跨页选择，逐项返回执行结果
- 新增代理 WebSocket 连接上限，由使用同一代理的账号共享，默认 `0` 表示不限制；当前仅约束单进程内原生 OpenAI Responses WebSocket 连接
- 统一服务器直连出口位置检测，保留本仓库的按钮反馈，以及显式代理失败后不回退直连的行为

## 兼容与稳定性

- 补齐 multipart 图片编辑请求转换，保留现有 JSON 请求支持；独立 Search 接口遵守模型访问规则
- 修复 Dashboard 昨日统计的时区边界、异步分页状态及会话资源生命周期问题
- PostgreSQL 与 Redis 密码统一要求 16–128 字节，正确处理字面百分号；符合要求的现有密码可继续使用
- 保留 OpenAI 请求字段顺序与 OAuth 请求顺序，不主动添加专项计时请求头；移除缺少可靠来源的引擎 TTFT 和 Token 间隔字段，保留请求级首字计时及现有速率计算
- 更新 ZIP 依赖的安全修复，整合上游发布校验与构建流程

## 升级事项

- 上游基线为 `v3.29.3`，提交 `16d8a3f87309d9346a5f204673390fe20478b40e`
- 本次涉及数据库结构变更：从 `v3.28.0+lqy007700` 升级追加 `0035_proxy_and_reset_credits.sql`，已有 `0001`–`0034` 迁移及校验值保持不变；升级前备份数据库，不要用上游同编号迁移覆盖本仓库文件
- 插件 RPC 协议升级为 `v4`，旧插件须使用匹配的 SDK 与 CLI 重新构建，不能仅修改版本声明；调度能力为 `scheduler v3`，完整兼容要求以发行附件中的兼容清单为准
- 代理创建与测试接口改为 1–100 项数组，单项也须使用数组；HTTP 200 表示批次被接收，调用方须检查逐项状态，不应自动重试整个批次
- Key 用量查询新增 `all` 类型及细分状态；Key 错误筛选仅含失败与未完成，管理端错误筛选继续包含取消
- API 与插件 SDK 移除 `upstreamEngineIapiTtftMs`、`upstreamEngineServiceTtftMs`、`upstreamEngineIapiTbtMs`、`upstreamEngineServiceTbtMs`，调用方应停止依赖这些字段
- 构建工具链更新为 Node.js `26.12.0` 与 Rust `1.99.1`；继续使用本仓库安装源与更新源，提供 Linux amd64 归档和容器镜像，Docker 镜像标签为 `3.29.3-lqy007700`
