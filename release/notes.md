# v3.28.0+lqy007700

## 请求恢复与调度

- 修复 `response.metadata` 被识别为不可重放事件的问题，仅收到可替换前导事件后遇到可恢复故障时，保留同账号重试与换号资格
- 保留本仓库的恢复策略：容量拒绝、可恢复的显式 `500`、`503` 和无状态码 `server_error` 共享请求内额外 5 次恢复预算，先在原账号额外重试最多 3 次，再逐次换号最多 2 次
- 区分暂时繁忙与被策略排除的账号，插件过滤结果同时约束选号、亲和重选和排队，避免绕过过滤或将繁忙误判为账号不可用
- 移除高权重账号自动回切选项，保留智能调度系数、账号亲和和原生续接约束

## 请求记录与诊断

- 请求列表继续默认显示所有请求，保留文字状态筛选、尝试次数、错误摘要、未完成错误弹层和折叠统计，并补充状态图标
- 诊断包改由后端收集生成，使用 `schemaVersion: 6`，包含已保存的关联请求、错误详情、时间线、事发配置和导出时网关版本，页面仍可查看诊断时间线与恢复关联
- 保留本仓库的重试阻断原因、同账号与换号判定、退避及剩余预算，补充准备与执行阶段、恢复意图和插件否决事实
- 诊断下载重新脱敏认证信息，并标记读取失败、未采集、过期、淘汰和截断等缺口，不能补回未保存的信息

## 分组权限与默认设置

- 分组新增允许生图设置，Client Key 绑定的任一分组禁止生图时，限制 Images 调用及 Responses 原生生图工具，普通图片输入不受影响
- 初始账号并发上限调整为 5，已保存的自定义运行设置保持原值

## 升级事项

- 上游基线为 `v3.28.0`，提交 `447869860a0fb88f78109cdb700db0cb1eb5d8b5`
- 从 `v3.27.6+lqy007700` 升级追加 `0034_group_image_and_scheduling.sql`，旧 `0032`、`0033` 迁移及校验值保持原样，新增生图权限并清理自动回切配置
- 调度插件能力升级为 `scheduler v2`，使用 `scheduler v1` 的插件需升级到匹配版本，其他能力以发行附件中的兼容清单为准
- 新诊断包结构与旧版 `schemaVersion: 5` 不兼容，包含脱敏后的错误原文与业务上下文，分享前仍需检查业务内容和内部关联信息
- 已交付实际输出、工具活动或其他不可重放事件后仍停止透明重放，仅凭上游 `503` 或 `firstTokenMs=null` 不能判定请求可重试
- 继续使用本仓库的安装源与更新源，提供 Linux amd64 归档和容器镜像，Docker 镜像标签为 `3.28.0-lqy007700`
