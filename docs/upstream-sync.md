# 上游升级与合并清单

同步操作与版本规则见 [main 分支维护](development.md#main-分支维护)，二开逻辑、代码与测试入口见[二开行为与维护索引](fork-behavior.md)。发行内容以对应 Git tag 和 Release 为准，本文不代表运行实例已经部署该版本

## 每次同步时维护

1. 核对工作区与远端，记录当前发行 tag、提交和目标上游稳定 tag；只读分析冲突和完整差异，分别列出采用、保留和待选项
2. 对照[二开行为与维护索引](fork-behavior.md)逐项追踪调用链，核对自动合并的代码，不能只检查冲突文件；需要改变保留项时先取得用户选择
3. 检查当前已部署迁移的编号与 checksum，新增迁移只追加；同时核对 API、子模块和构建工具链
4. 按影响验证请求恢复、页面交互、数据库升级和发布流程；通过、失败、跳过和未执行分别报告，不把旧版也存在的失败计为通过
5. 就地更新本文的基线、能力表和待选提交，并同步二开维护索引，移除已失效项；逐版本的发行变化留在对应 tag 的 `release/notes.md` 与 Release，不在本文追加历史章节
6. 按本轮授权分别完成本地修改、提交推送、发布或部署；用户要求停止跟踪发布时，交付任务链接，不把成功触发当作产物发布成功
